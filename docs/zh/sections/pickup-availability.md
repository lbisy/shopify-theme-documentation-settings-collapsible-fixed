# Pickup Availability（到店取货状态）

**Pickup availability** 用于在商品页面显示当前所选商品变体能否在门店取货。它是一个由 Shopify 数据驱动的组件：门店名称、取货状态、备货时间、地址和电话均来自 Shopify，并不是在当前分区中手动填写。

::: warning 当前分区没有可配置项
代码中的 `settings` 数组为空，并且没有 preset。主题编辑器不会提供内容或布局设置，这个分区也不是供商家像普通自定义分区一样添加的。它在页面中的位置以及切换变体后的刷新行为由商品模板和主题代码控制。
:::

## 顾客看到的内容

当前变体至少存在一个已启用到店取货的地点时，分区会显示：

- 第一条门店记录的状态图标，以及“可在该地点取货”或“无法在该地点取货”的提示。
- 第一家门店可取货且提供了备货时间时，显示预计取货时间。
- 只有一个取货地点时，显示可展开的 **View store info（查看门店信息）** 链接。
- 有多个取货地点时，显示可展开的 **Check other stores（查看其他门店）** 链接。
- 展开后列出所有已启用到店取货的地点，包括名称、当前状态、格式化地址、可选的取货时间和可选的电话号码。

可取货地点使用勾选图标，不可取货地点使用关闭图标。图标设置了 `aria-hidden="true"`，因为相同状态已经通过文字提供给辅助技术用户。

## 显示条件

代码读取 `product_variant.store_availabilities`，然后只保留 `pick_up_enabled` 为 `true` 的记录。

| 条件 | 页面结果 |
| --- | --- |
| 没有已启用取货的门店记录 | 不渲染可见的取货卡片，内容容器标记为 `data-empty="true"`。 |
| 存在一条或多条取货记录 | 渲染取货卡片，内容容器标记为 `data-empty="false"`。 |
| 第一家门店可取货 | 显示可取货提示；存在取货时间时同时显示该时间。 |
| 第一家门店不可取货 | 显示不可取货提示，并且不显示该门店的取货时间。 |
| 只有一家门店 | 展开链接使用 `view_store_info` 翻译。 |
| 存在多家门店 | 展开链接使用 `check_other_stores` 翻译。 |

筛选条件是门店是否启用了到店取货，而不是当前变体是否有货。因此，不可取货的门店仍会保留在展开列表中。摘要始终使用返回结果中的第一条记录；当前分区本身不会计算距离或重新排序。即使摘要门店不可取货，后续门店仍可能可取货。

## 每家门店显示的信息

展开列表会为每条已启用取货的记录显示以下数据：

- **门店名称**：来自 `availability.location.name`。
- **Available（可取货）** 或 **Unavailable（不可取货）**：由 `availability.available` 决定。
- **取货时间**：来自 `availability.pick_up_time`，仅在门店可取货且该值不为空时显示。
- **地址**：来自 `availability.location.address`，并通过 Shopify 的 `format_address` 筛选器格式化。
- **电话号码**：`address.phone` 不为空时显示。

电话号码仅以普通文字显示；当前代码不会生成 `tel:` 拨号链接，也不会生成地图链接。请在 Shopify 后台保持每个地点的公开名称、地址、电话、取货状态和备货时间准确。

取货状态和预计时间可能包含门店调拨库存。即使商品当时不在该地点现货库存中，只要可以通过调拨供应，门店也可能显示为可取货；此时 Shopify 提供的取货时间应包含相应的准备或调拨时间。

## 变体切换与动态刷新

到店取货状态属于具体商品变体，而不是整个商品。切换颜色、尺寸等选项后，门店列表和取货状态都可能变化。

`data-pickup-availability-fragment`、`data-pickup-availability-content` 和 `data-empty` 属性为主题 JavaScript 提供了更新入口。当前 Liquid 文件本身不会监听变体切换，也不会发起网络请求。商品页外围代码必须完成以下流程：

1. 识别顾客新选择的商品变体。
2. 在该变体的渲染上下文中请求 Pickup availability 分区。
3. 使用返回内容替换页面中原有的取货片段。
4. 正确处理空响应或请求失败，避免继续显示上一个变体的旧状态。

如果切换变体后状态没有变化，应检查商品表单的变体变更事件、分区渲染请求、返回的 HTML 和片段替换逻辑。同时确认请求中的变体处于选中状态或属于第一个可售变体，因为 Shopify 只会在这些上下文中定义 `variant.store_availabilities`。

## 主题样式与交互

当前分区没有独立的颜色或间距设置。边框、背景、文字、留白、焦点环和展开动画均继承主题令牌及工具类。

门店列表使用原生 `<details>` 和 `<summary>` 元素。顾客可以使用鼠标或键盘展开列表，展开时箭头会旋转。请使用 `Enter`、`Space`、触控操作和屏幕阅读器进行测试，并确认商品页采用的每种配色方案都能清楚显示状态文字、边框和焦点标识。

## 多语言文字

顾客可见的状态和操作文字来自以下语言键：

- `products.product.pickup_availability.available_at_html`
- `products.product.pickup_availability.unavailable_at_html`
- `products.product.pickup_availability.view_store_info`
- `products.product.pickup_availability.check_other_stores`
- `products.product.pickup_availability.available`
- `products.product.pickup_availability.unavailable`

前两个语言键会接收 `location_name`，并且可以包含 HTML。请检查每种已发布语言是否缺少语言键、插入门店名称后的语序是否自然，以及可取货和不可取货的表述是否清晰。取货时间由 Shopify 提供，也应在每种店面语言下检查。

## 商店设置检查

测试本分区前，请确认：

1. 至少一个 Shopify 地点已经启用到店取货。
2. 该地点已经关联当前商品变体的库存。
3. 该地点已配置取货可用性和备货时间。
4. 对外显示的地点名称、地址和可选电话号码准确无误。
5. 商品模板包含当前分区所需的取货容器及动态刷新脚本。

当前分区只负责展示 Shopify 的取货数据，无法启用到店取货、分配库存、修改备货时间或编辑地点联系信息。

## 发布前检查

1. 分别测试只有一家取货门店和存在多家取货门店的商品。
2. 测试可取货、不可取货以及没有取货记录的变体。
3. 不刷新页面地切换所有变体，确认内容及时更新且不会保留旧状态。
4. 检查摘要门店、状态图标、取货时间和展开链接文字。
5. 展开列表，确认每家门店的状态、地址和可选电话号码正确。
6. 检查空状态，确保页面不会留下空白边框卡片或上一变体的旧门店信息。
7. 测试较长门店名称、多行地址、缺少电话号码以及缺少取货时间的情况。
8. 检查桌面端和移动端的换行、对比度、焦点可见性与展开动画。
9. 分别使用鼠标、键盘、触控和屏幕阅读器测试交互。
10. 在每种已发布的店面语言下重复检查。

开发实现可参考 Shopify 的[到店取货可用性指南](https://shopify.dev/docs/storefronts/themes/delivery-fulfillment/pickup-availability)。
